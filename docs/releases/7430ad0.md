## 3. P0-7 exposure assessment

**Defects, all on a public unauthenticated unthrottled endpoint:**

1. `worker.upsert` overwrote an existing account's `passwordHash` — account takeover from a known email.
2. `organization.upsert` keyed on a **public EIN** returned the victim's org, renamed it, bound the attacker via `WorkerOrgRelationship`, and issued a session with `role: 'admin'` hardcoded.
3. `subscriptionTier: 'STARTER'` + `@default(ACTIVE)` minted entitled orgs that `scheduler.ts` ran billable agent work for.

**Reachability, measured:** unauthenticated `GET /api/auth/register` returned **405** (route live, POST-only) — CI run [32379291026](https://github.com/chiosemen/magnus-non-profit-services/actions/runs/32379291026). No write path was exercised; no exploitation attempted.

**Data within reach — measured, not assumed:**

```
{"orgs":6,"workers":11,"donors":2}
```

**Conclusion:** the exposed database was **not empty**. 6 organizations, 11 workers, and 2 donor records were reachable through the defective endpoint for the period it was deployed. Every one of those 11 worker accounts had an overwritable password hash; every one of those 6 organizations could be attached to by anyone knowing its EIN. Whether these rows are seeded test data or real prospect records is **for the operator to characterise** — the count alone does not say.

No evidence of exploitation was observed. No log review was performed.
